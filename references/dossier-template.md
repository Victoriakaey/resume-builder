# Per-User Dossier — read this FIRST every session

The resume-builder skill's personalization file: what's been learned about YOU + your
projects, so a fresh session doesn't re-ask, re-derive, or re-make old mistakes. **Read
before touching a bullet — this overrides the skill's generic defaults.**

Companion to your `strategy.md` / `profile.md` / `decisions.md` (positioning/lane/constraints
live there — do NOT duplicate them here). This file adds the three things those don't capture:
**project POINTS in your own words**, **off-limits claims (guardrails)**, and
**preferences/corrections**.

**Conventions:** guardrails sit at the TOP as a scannable checklist, one line each with a
`[short-handle]` and a date. Preferences carry a `[durable]` or `[context:<scope>]` tag plus a
date so stale ones can be retired. The corrections log is append-only. A new learning that
contradicts an old entry SUPERSEDES it — mark the old one `retired (superseded by <new>, DATE)`
and add the new; never silently delete (history explains why it changed).

---

## 1. Guardrails — off-limits / handle-with-care (scan before writing ANY bullet)

Claims never to re-propose, or to handle carefully. One line each, dated.

- [example-handle] <the rule, one line — what not to say and lead with instead> — YYYY-MM-DD

## 2. Project points — IN YOUR OWN WORDS (the soul, NOT the mechanisms)

Per project: the one-sentence point (what it's FOR) + source. Not a feature list.

- **<Project>** (<source: their-site.com / from you>) — <one-sentence point>.

## 3. Preferences — register / voice / process (apply from word one)

Each tagged `[durable]` (always true) or `[context:<scope>]` (only in some situations), dated.

- [durable] <a register / voice / process preference> — YYYY-MM-DD
- [context:<when>] <a preference that only applies in that context> — YYYY-MM-DD

## 4. Corrections log — append-only, dated

When you corrected a pattern → the durable lesson.

- YYYY-MM-DD — "<what you said>" → <the durable lesson>.
